# Agent Note: MCP Qwen 视觉识别回退

Status: implemented

[English](2026-08-16-mcp-qwen-vision-fallback.md) | 中文

## Problem

纯文本模型可以在用户请求中收到图片附件，却无法检查像素内容。现有 MCP 管理页只能列出已发现的工具和本地生图桥接，没有多模态回退能力，也没有安全配置回退服务凭据的位置。

## Decision

本地 MCP 图片桥接在 `mcp__image__generate_image` 旁注册 `mcp__vision__analyze_image`。视觉工具选择最新用户消息中的持久图片附件，在 Host 读取已校验的字节，并把文字要求与 `image_url` 数据发送到 OpenAI 兼容的 Qwen 接口。默认模型是 `qwen3.7-flash`，默认地址是 DashScope 兼容模式基础地址。工具结果保持为文本，这样纯文本调用方可以继续当前轮次，而不会收到图片块。

桥接注册 `mcp-image-generation` 设置命名空间，其中 API Key 使用只写 secret 角色，并配置凭据引用。MCP 管理页展示 Key 与引用控件，只通过 `credentials.set` 写入字面量，并把模型和地址作为状态元数据展示。Host 永远不会返回 Key，浏览器也不会在设置快照中收到密钥。

## Alternatives considered

**让视觉能力复用当前的 `ctx.llm` provider。** 这会让回退能力依赖一个自身可能只有文本能力的模型目录，并把工具级能力耦合到无关的路由选择。独立的 OpenAI 兼容请求能明确管理 Qwen 凭据和地址行为。

**要求文本模型在工具参数中传附件 id。** 纯文本模型无法可靠地生成或恢复不透明的附件元数据。根据 agent 会话自动选择最新用户图片可以覆盖通常的用户流程，同时保留显式图片引用供程序化调用。

**把 API Key 存进 MCP 设置文档。** 设置 descriptor 虽然会脱敏，但文档中的字面量仍会扩大持久化和同步暴露面。凭据引用配合只写凭据 API 可以保持现有的密钥边界。

**返回识别图片或多模态工具结果。** 该工具的目的，是给纯文本模型提供视觉事实；返回原图字节不会增加能力，还可能让后续文本请求失败，因此结果保持为有界文本回答。

## Consequences

纯文本模型可以通过一个普通 MCP 工具识别当前用户图片，不需要修改模型路由。Qwen 请求支持取消并使用持久附件字节，API Key 仍由 Host 持有。MCP 管理页在只读能力目录旁增加了紧凑的凭据表单；缺少设置或连接服务的部署仍可正常使用能力目录，并隐藏可选配置表单。
