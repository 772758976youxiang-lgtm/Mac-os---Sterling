# Agent Note: 显示工具调用开关

Status: implemented

[English](2026-08-18-show-tool-calls-toggle.md) | 中文

## 问题

通用设置面板可以控制上下文注入记录在会话记录中的显示,却没有对应的工具调用显示开关。大量使用工具(尤其是 MCP 集成)的会话会产生被工具调用行占据的长会话记录,且无法在不隐藏后续助手回复的情况下将其隐藏。

## 决策

`ui-conversation` 设置分节新增持久化偏好 `showToolCalls`(默认 `true`),由通用设置中紧跟在上下文注入行下方的「显示工具调用 / Show tool calls」开关行控制。`ChatNodeSeat` 在该偏好关闭时跳过 `tool-call` 节点,因此工具行(及其结果内容)消失,而用户消息与助手回复保持可见;该偏好与 `showContextInjections` 一样仅影响展示,绝不改变模型接收到的内容。生成的图片是例外:结果元数据中带图片的工具结果在偏好关闭时仍以裸图库渲染,因为产出的图片本身就是用户想要的答案,不应被会话记录的开关隐藏。设置存放在与上下文注入偏好相同的 `ConversationDisplaySettings` store 与 Host settings scope 中,跨刷新持久生效,并实时应用。

## 曾考虑的替代方案

**按工具名前缀过滤(只隐藏 MCP 工具)。** 不予采用:用户要求的是会话级的工具调用显示开关,按名称过滤会静默隐藏一部分工具而保留另一部分;纯展示开关与上下文注入开关保持统一的心智模型。

**在 reducer/快照层隐藏工具行。** 不予采用:显示偏好属于视图层;日志与快照保持完整,轨迹视图与任何未来界面仍可读取这些调用。

## 后果

关闭开关会得到更干净的会话记录,代价是聊天内不再保留「运行了哪些工具」的记录(轨迹/详情视图仍可查看)。助手回复仍然可见,回答的脉络不受影响;生成的图片以图库形式保持可见,因为它们本身就是答案。偏好可持久化、默认开启,并沿用上下文注入偏好的存储、接线与测试模式。
