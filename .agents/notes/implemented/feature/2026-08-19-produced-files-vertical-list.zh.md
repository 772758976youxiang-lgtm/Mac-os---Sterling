# Agent Note: 产物行改为完整纵向列表

Status: implemented

[English](2026-08-19-produced-files-vertical-list.md) | 中文

## 问题

完成一轮后出现的产物行把路径渲染成一条经过测量的单行 lane：至多六个 chip，其余折叠在精确的 `+ N 个文件` 剩余计数之后，一旦有隐藏文件还会出现**在文件夹中显示**操作。产出文件较多的轮次一眼只能看到前缀；剩余部分只是一个计数，而不是路径。当初为单行服务的整套测量机制——chip 探针、剩余计数探针、监听该行的 ResizeObserver——存在的唯一理由就是让这一行不换行。

## 决策

**该行改为完整纵向列表：每条产物路径独占一行，不做任何折叠。**标签仍在左侧；chip 在标签下按列堆叠，每项仍经属主提供的 `openFile` 打开，完整路径作为 `title`，并带本地化的打开标签。折叠正是测量机制的全部意义，因此整套测量 lane 机制被删除：`fitProducedFiles`、`SHOWN_LIMIT`、探针元素、`ResizeObserver`，以及 `+ N 个文件` 剩余计数（其两条本地化文案一并删除）。

**文件夹操作及其能力面随它所服务的溢出场景一起删除。**`在文件夹中显示` 的存在意义只是抵达被 lane 隐藏的文件；既然没有任何文件被隐藏，溢出场景不复存在，按钮、`isLoopback`／`hostDescription` 注入面，以及插件的 `connection` 服务边全部随之移除。该行现在只接收属主 props 与 locale 席位。

**e2e 与组件覆盖从测量转向完整性。**Web e2e 冷播种十次写入，现在断言十个 chip 全部渲染、无剩余计数文本，且 chip 处于互不相同的纵向位置；组件 spec 断言每条路径都渲染为可打开的 chip，空轮次渲染零个。

## 备选方案

**保留测量 lane，仅提高上限。**拒绝：任何上限仍会折叠；需求是每个产物文件都可见。

**按目录分组折叠。**拒绝：对常见场景而言是多余的复杂度；列表通常很短，路径已按首见顺序去重。

## 影响

产出文件较多的轮次改为纵向增长，而不是藏起大部分文件，代价是纵向空间。插件更小了：少一条服务边、少一个注入面、零测量代码，两份字典中的 `在文件夹中显示`／`+ N 个文件` 文案也随之消失。收尾正文的文件提及（`chatFileMentions`）不受影响。
