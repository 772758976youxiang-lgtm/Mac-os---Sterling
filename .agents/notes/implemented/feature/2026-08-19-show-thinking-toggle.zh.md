# Agent Note: 显示思考过程开关

Status: implemented

[English](2026-08-19-show-thinking-toggle.md) | 中文

## 问题

通用设置可以隐藏会话记录中的上下文注入与工具调用行,却没有任何控制助手思考过程(推理块)的开关。使用带推理能力模型的会话会在每个推理块前展开「思考 / Think」折叠行,用户无法只阅读答案而跳过思考脚手架。

## 决策

`ui-conversation` 设置分节新增持久化偏好 `showThinking`(默认 `true`),由通用设置中位于工具调用行正下方的「显示思考过程 / Show thinking process」开关行控制。该偏好与 `showContextInjections`、`showToolCalls` 一样仅影响展示,绝不改变模型接收到的内容。`ChatView` 从共享的 `ConversationDisplaySettings` store 读取该偏好,经由 `ChatNodeSeat` 作为聊天节点 owner 货币传入,`AssistantMarkdown` 在任何可见性判断之前丢弃 `reasoning` 块:只含被隐藏思考的助手节点整体折叠,文本答案保持可见。设置与其它可见性偏好存放在同一个 Host settings scope 中,跨刷新持久生效,并实时应用。仅含思考的流式轮次在文本到达前不显示任何内容;轮次级运行状态仍保持可见。

## 曾考虑的替代方案

**在会话日志/reducer 层跳过思考。** 不予采用:显示偏好属于视图层;日志与快照保持完整,回放与任何未来界面仍可读取思考内容。

**复用工具调用行,把思考当作工具调用子类型隐藏。** 不予采用:思考渲染在助手节点内部(是块,不是 `tool-call` 聊天节点),工具调用节点的过滤无法触及它;独立的纯展示开关与另外两个可见性行保持统一的心智模型。

## 后果

关闭开关会得到聚焦于答案的更干净会话记录,代价是聊天内不再展示模型的可见思考轨迹(会话日志仍记录思考内容,轮次流式期间轮次级运行状态仍然可见)。偏好可持久化、默认开启,并沿用上下文注入/工具调用偏好的存储、接线与测试模式。
