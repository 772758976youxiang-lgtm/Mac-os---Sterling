# Agent Note: 移除无限创作模式

Status: implemented

[English](2026-08-17-remove-infinite-creation-mode.md) | 中文

## 问题

Sterling 是以会话和工作区为中心的应用。侧边栏的模式切换引入了一个独立的本地画布，会改变应用框架，却不服务于主要的会话工作流。

## 决策

Web App 组合包不加载 `@deepseek-ai/dsh-client-ui-infinite-canvas`。该包、Canvas 存储、模式菜单、全屏覆盖层、locale 文案、测试和类型项目引用均不在仓库中。浏览器因此没有模式按钮、无限创作画布或本地持久化的画布文档。

其余模型、权限和 Agent 预设选择控件保留各自独立的职责。它们不选择应用框架，仍在原有位置提供。

## 考虑过的替代方案

**只隐藏侧边栏按钮。** 画布代码和已存储的模式状态仍可通过已加载的插件访问，产品中会留下不受支持的应用框架。

**保留休眠的画布包。** 仅从组合包排除的包仍会保留没有产品负责人的陈旧源码、类型、依赖和目录内容。

**移除所有名为模式的控件。** 模型、权限和 Agent 预设控件表达的是正常会话工作所需的独立选择；相同的标签不会让它们成为同一个功能。

## 测试

冷启动空会话的 Web 场景断言已发布的英文界面既不包含 `Mode` 按钮，也不包含无限画布覆盖层。

## 后果

侧边栏从 Sterling 品牌直接进入新会话和工作区操作。本地节点画布及其按工作区保存的文档不可用。重新引入独立的应用框架需要新的产品决策和专用插件。
